# デモ用の利用実績を作る手順（任意）

検証・デモ用テナントで、ほとんどのユーザーが Copilot を使っていないときに、利用の濃淡（ハード / ふつう / 未使用）を作る方法です。**自分が管理するデモテナントだけ**で行い、本番テナントでは行わないでください。

## 前提（先に確認すること）

| # | 前提 | 確認方法 |
| --- | --- | --- |
| 1 | 対象ユーザーに Microsoft 365 Copilot のライセンスが付いている | 管理センターのライセンス、または Graph の `assignedPlans` |
| 2 | 一時アクセスパス（TAP）が認証方法ポリシーで有効 | Entra の認証方法 > ポリシー |
| 3 | 操作する管理者が、対象ユーザーの認証方法を管理できるロールを持つ（例: 認証管理者以上） | Entra のロール割り当て |
| 4 | 委任権限 `UserAuthenticationMethod.ReadWrite.All` と `User.Read.All` に管理者の同意が済んでいる | 同意が無ければ管理者承認が必要（自動では付けない） |
| 5 | 条件付きアクセスの変更・回避をしない | TAP でサインインできる設計のテナントのみ対象 |

## 流れ

1. 管理者として Graph の委任トークンを取る（トークンは保存・表示しない）。
2. 対象ユーザーごとに TAP（有効 60 分）を発行する。
3. 別プロファイルの InPrivate ブラウザで、そのユーザーとして TAP でサインインする。
4. Copilot チャットに、層ごとの回数だけ依頼する（例: ハード 10 回、ふつう 2〜3 回）。
5. TAP を削除し、ブラウザのプロファイルを破棄する。

## 守ること

- TAP の値・トークンをログや成果物に書かない。使い終わったら必ず削除する。
- 層ごとの回数と対象人数は、実行前に決めて記録する。
- 実績が Graph の利用状況レポートに載るのは翌日以降になる（当日のダッシュボードには出ない）。
- 管理者承認・追加費用・テナント全体の設定変更が必要になったら、そこで止めて本人に確認する。

## 公開リポジトリに含めないもの

実行スクリプトはテナントごとの設定（テナント ID・クライアント ID・ライセンス識別子）をパラメータで受け取る非公開側の資産です。この公開リポジトリには手順の考え方だけを置きます。
